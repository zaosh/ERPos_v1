ERPos

Inventory and point-of-sale system built for a physical thrift store. Computer-vision assisted intake, thermal receipt POS, customer tracking, returns, and an analytics dashboard — all in one system.

Backend FastAPI + Python
Database PostgreSQL 16
Frontend React 18 + TypeScript
CV K-means + GPT-4o + FashionCLIP
Queue PostgreSQL workers
Print ZPL → Zebra thermal
Currency INR (₹)

Features

Intake

Camera & CV

  • Webcam capture with motion detection — auto-fires when garment is still
  • K-means color detection: instant, local, ~50ms
  • GPT-4o-mini fills item type in the background (seconds)
  • CV confidence displayed — below 0.4 flagged for manual review
  • Full CV output stored as JSONB for debugging and future fine-tuning

Form & Print

  • Fields: category, color, size, condition, price (₹), label, notes
  • Bulk intake mode — queue multiple items, confirm all at end
  • Barcode label prints automatically on confirm (Code128, ZPL)
  • Print queue retries automatically if printer is offline
  • Reprint any item from Inventory without re-entering data

Checkout (POS)

Cart & Receipt

  • Scan or type barcode — items added instantly to cart
  • Live thermal receipt renders as items are scanned (warm off-white paper style)
  • Click any price on the live receipt to override inline
  • Item count badge + running subtotal always visible

Customer & Payment

  • Phone lookup — auto-fills name, shows returning customer badge
  • Returning customer flag shown on printed receipt
  • Discount: flat ₹ or % (quick chips: 10 / 15 / 20%)
  • Payment: Cash / Card / Other
  • Cash tendered buttons (₹100 / ₹500 / ₹1000 / ₹2000) + live change-due

Keyboard Shortcuts

  • F2 — toggle customer panel
  • F3 — jump to discount field
  • F12 — complete sale
  • Backspace — remove last item
  • Esc — void cart

Post-Sale

  • Sale complete screen with full receipt fetched from DB
  • Print receipt button
  • "Another for [Customer]" shortcut — keeps customer, clears cart
  • Customer auto-created if name + phone provided and not on file

Sales History & Returns

Bill Search

  • Search by sale ref (SALE-YYYYMMDD-NNN) or receipt number (RCP-…)
  • Receipt renders in the same thermal-paper format as live checkout
  • Returned items shown struck-through with RETURNED label
  • Customer, cashier, payment method, itemised totals all visible

Return Flow (admin)

  • Days-since-purchase banner: green / amber (≤3 days left) / red (expired)
  • Checklist of items — already-returned items disabled and struck through
  • Reason text field + refund method: Cash / Card / Store Credit
  • Resellable toggle: ON → item back in stock at original barcode; OFF → archived
  • Return window enforced server-side from system settings

Inventory

Browse

  • Grid (thumbnail cards) and table views
  • Filter by status, category
  • Search by label or barcode (searches both fields)
  • Pagination

Item Actions

  • Inline status change: in_stock → sold / reserved / archived
  • ↩ returned badge on items that have passed through a return
  • ★ excellent condition badge in grid view
  • Image thumbnails from intake

Analytics (admin)

Revenue & Sales

  • Today's revenue hero strip with 7-day sparkline
  • Stat cards: total items, in stock, sold, revenue, avg price/item
  • Configurable period: 7d / 30d / 90d
  • Sales trend line chart — grouped by label, color, or category

Inventory Intelligence

  • Category sell-through heatmap
  • Dead stock alerts — items unsold for N+ days (configurable)
  • Avg days-to-sell by category and condition

CV Performance

  • Overall accuracy %, needs-review %
  • Per-type accuracy breakdown
  • Top misclassifications

Operations

  • Job queue monitor — pending, failed, retry counts
  • Retry failed print/CV jobs from the UI without terminal access

Customers

Profile

  • Created at checkout or via API
  • Fields: name, phone, email, notes
  • Total purchase count tracked
  • Returning customer flag shown on receipts

Lookup

  • Phone-based real-time lookup (debounced, 7+ digits)
  • Auto-fills name on match during checkout
  • Linked to sales and returns by customer UID
  • GDPR erase support

Data Model

items

Core record. barcode, category, color, type, label, size, condition, price NUMERIC(10,2), status, image_path, cv_raw_output JSONB. Soft-deleted via deleted_at — never hard-deleted.

sales + sale_items

sale_ref, receipt_number, customer_id, subtotal, discount_amount, tax_rate, tax_amount, total_amount, payment_type. sale_items records price at time of sale.

customers

customer_uid, first_name, last_name, phone, email. Linked to sales and returns. GDPR erase supported.

returns + return_items

return_ref, original_sale_id, return_reason, refund_method, refund_amount, status. Each item can appear in at most one return (unique constraint).

job_queue

Tracks every CV analysis and print job. status, attempts, next_retry_at, error_message. Workers poll with SKIP LOCKED — no job runs twice.

audit_log

Every write operation logged: table_name, record_id, action, old_values JSONB, new_values JSONB, user_id, ip_address.

system_settings

Runtime key-value config: store name, tax rate, return window days, receipt footer. Editable without a deploy.

users

Roles: staff, admin, superadmin. bcrypt-hashed passwords. Linked to items (created_by), sales (cashier), returns (processed_by), audit log.
